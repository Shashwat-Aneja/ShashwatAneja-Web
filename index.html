02 / INTRODUCTION

The reason underneath the work.

A QUESTION
CAN BECOME
A SYSTEM.

I started by wanting to know what happened behind the screen.

Then I learned that curiosity becomes much more useful when you can build the thing you are wondering about. A small program can become a game, an interface can become a system, and a question can become a prototype.

I move between software, games, AI, hardware and design because each one exposes a different part of the same problem: understand something, make it tangible, see where it breaks, rebuild it better.

08 / HOW I THINK

Working principles, not slogans.

01

Technology is not the experience.

A stack can enable an idea, but it should not become the idea.

02

Interaction should have a reason.

If a motion or control does not help someone understand, discover or feel something, it probably does not belong.

03

Constraints sharpen ideas.

Fewer moving parts can make the important part easier to see.

04

Build enough to disagree.

A working prototype gives an idea something concrete to push against.

05

Rebuilding is part of learning.

Sometimes the fastest route to understanding is making the thing again from first principles.
